Documentation

Everything you need to install, run and extend Mav.

Installation

On a fresh Debian/Ubuntu machine:

curl -fsSL https://raw.githubusercontent.com/SoaOaoS/mav/main/get.sh | sudo bash

Or clone and run the installer directly:

git clone https://github.com/SoaOaoS/mav.git
cd mav
sudo ./install.sh

A wizard asks a few things once — contact email, Telegram token, model provider, Postgres, dashboard — then does everything else: dependencies, database, TLS certificates, VAPID keys, three systemd services, and a health check.

The installer never touches your opencode agent config beyond a minimal provider block. Your MCP servers, custom agents and skills are yours.

Installer modes

Mode What it does
./install.sh Install, or detect an existing install and update it
./install.sh --update Update, keeping your config
./install.sh --yes All defaults, no questions
./install.sh --dry-run Show what would happen, change nothing
./install.sh --uninstall Remove services, configs and the container

Updating

Updating never re-asks your settings. The installer remembers your configuration in the generated env files, and installs a mav command: 

mav update        # update code and services, keep your config
mav reconfigure   # re-run the wizard to change settings
mav status        # service status
mav logs          # follow the bot logs
mav uninstall

Even simpler: just re-run the installer. If an install exists, it asks a single question — [U] update (keep my config) or [R] reconfigure — defaulting to update.

Requirements

  • A Debian or Ubuntu machine (tested on Debian 13).
  • Root access (the installer uses sudo).
  • A model: Ollama (local), Claude, OpenAI, or any OpenAI-compatible endpoint.
  • A Telegram bot token from @BotFather.
  • Docker is installed automatically if missing.

Architecture

Mav is three small pieces plus a database.

Telegram ─┐
          ├─▶ mav-bot ──────┐
Browser ──┴─▶ mav-dashboard ┤
                            ▼
                   opencode engine (:4096)
                            │
                            ▼
                  Postgres (Docker)
  • opencode is the agent engine. It runs the model, the agents and the tools. You configure it yourself.
  • mav-bot is the Telegram bridge. It also runs the watch loop and the job scheduler.
  • mav-dashboard serves the web UI and the HTTP API.
  • Postgres stores memory, watch items, notifications and the RAG index.

Services

Service Role
mav-server opencode engine on 127.0.0.1:4096
mav-bot Telegram bridge + watch + jobs
mav-dashboard Web interface (HTTP/HTTPS) 
systemctl status mav-server mav-bot mav-dashboard
journalctl -u mav-bot -f
journalctl -u mav-dashboard -f

Model providers

The wizard lets you pick one:

Provider What you need Example model
ollama A running Ollama llama3.1, qwen2.5-coder
anthropic An ANTHROPIC_API_KEY claude-sonnet-4-5
openai An OPENAI_API_KEY gpt-4o
custom An OpenAI-compatible endpoint + key depends

The installer writes a minimal ~/.config/opencode/opencode.json with your provider and puts the API key in the engine's environment (/etc/mav-server.env).

Agents

An agent is a Markdown file with YAML frontmatter and a prompt, in ~/.config/opencode/agent/. The installer ships a set of generic templates (dev, research, writer, ops, finance, reviewer, orchestrator) without overwriting anything you already have. 

---
description: Short description of what this agent does
mode: subagent
---

You are <role>. <What you do and how.>

Rules:
- <rule>

You can create, edit and delete agents from the dashboard (Settings → Agents), or by hand. Restart the engine to make them available: 

mav update     # or: systemctl restart mav-server

Orchestrator

Mav ships with an orchestrator agent. Its default behaviour is not to answer everything itself, but to:

  1. analyse the request and decide the plan;
  2. convene the right specialists with opencode's task tool;
  3. have them challenge each other when they disagree;
  4. synthesise one clear answer, honest about uncertainty.

Default pairings: code → dev + reviewer; research → research + reviewer; writing → writer + research; finance → finance + research; ops → ops + reviewer. Edit agents/orchestrator.md to change the policy.

MCP servers

MCP (Model Context Protocol) servers give your agent extra tools — GitHub, Notion, a database, your own services. They live under the mcp key of opencode.json and are fully yours: the installer sets none.

Manage them in the dashboard (Settings → MCP servers), where secrets are masked on read and preserved on write, or edit the config directly: 

{
  "mcp": {
    "my-server": {
      "type": "remote",
      "url": "https://example.com/mcp",
      "enabled": true
    }
  }
}
Restart the engine after changing MCP servers. The dashboard has a one-click Restart engine button, or use systemctl restart mav-server.

Dashboard

The web interface has six views:

  • Home — greeting, quick actions, today's summary;
  • Conversations — a ChatGPT-style manager and a streamed chat;
  • Automations — scheduled jobs, run/pause;
  • Memories — everything Mav remembers, with search;
  • Watch — watched sources, add/remove;
  • Infra — your Proxmox nodes and VMs, live;
  • Settings — engine status, AGENTS.md, agents and MCP, with a restart button.
No authentication: expose it over a VPN or a private network, not the public internet.

Notifications

Mav reaches out through Web Push and Telegram. Subscribe to push from the dashboard (the bell button). Each notification carries a link: tapping it opens the dashboard and asks Mav to explain the alert.

  • Quiet hours (default 23:00–07:00) suppress pushes.
  • Duplicate keys prevent the same alert being sent twice.
  • Job notifications are short summaries; the full report stays in the dashboard.

Watch & jobs

Watch polls a source and alerts only on a change of state. Types: web (page changes), mail (unread matches), github (open PRs), proxmox (VMs), health (services), stock (level crossings and abnormal volume). 

/watch add stock AAPL:180:200:240
/watch add github myorg/myrepo
/watch add web https://example.com/status

Jobs run a prompt on a schedule. Define them in jobs.json in the bot directory, with a fixed time or an interval. A job that replies nothing to report is never sent.

Database schema

Applied automatically from scripts/schema.sql. Idempotent and safe to re-run.

Table Holds
conversations Finished exchanges (memory)
facts Durable facts about you
preferences Settings per chat
watch_items Watched sources and their state
documents RAG index (tsvector)
notifications Notification history + dedup

Troubleshooting

The engine is offline

systemctl status mav-server
journalctl -u mav-server -n 50

Check the model provider: a wrong key or endpoint is the usual cause.

status=203/EXEC

systemd could not execute the command. For the engine, Mav uses a launcher that resolves the opencode binary at runtime — so this only happens if opencode is truly missing. Install it and restart: 

curl -fsSL https://opencode.ai/install | bash
sudo systemctl restart mav-server

Installed opencode elsewhere? Point the launcher at it via MAV_OPENCODE_BIN in /etc/mav-server.env.

A reboot shows a failed unit

Run systemctl --failed and journalctl -b -p err to see what failed. Mav's own units are ordered after the network and are idempotent; the engine launcher retries until opencode is available.

The bot doesn't reply

journalctl -u mav-bot -n 50

An invalid Telegram token or a chat id not in the allowlist are the common ones.

The dashboard doesn't answer

journalctl -u mav-dashboard -n 50
curl -k https://<your-ip>/api/status

Start over cleanly

mav uninstall
docker volume rm mav_pgdata      # also wipes the memory
